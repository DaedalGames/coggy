# There is no knee: sessions cost each other from the very first ones

[Hours earlier the same evening](2026-08-02-204124-a-redline-without-a-solo-rung.md) the model behind every redline here was read as a measurement path: below saturation a hold's total output rises with slope `d/w`, above it sits flat at `η·C/w`, and the redline is twice where they meet. That derivation ended by saying it was a claim that a path exists rather than that anyone had walked it.

**Walked, it does not hold.** The rise is not a line, and the reason is that the loss starts long before saturation.

## The sweep

A hundred sessions as the reference, six points below it, a reference between every pair. Duty 0.27, 20 MiB resident, 180 s a hold, an uncounted warm-up before each.

| sessions | total | per session | added by the last four |
|---|---|---|---|
| 8 | 84.5 | 10.562 | |
| 12 | 122.4 | 10.200 | 37.9 |
| 16 | 145.8 | 9.113 | 23.4 |
| 20 | 176.8 | 8.840 | 31.0 |
| 24 | 191.6 | 7.983 | 14.8 |
| 28 | 194.7 | 6.954 | **3.1** |
| **100 (reference)** | **264.2** | 2.642 | |

**Per-session throughput falls 34% between eight sessions and twenty-eight**, and the marginal return of four more sessions collapses from 37.9 to 3.1.

## The residuals say it cannot be a line

Fitting `total = slope × N` through the origin over all six points gives 8.12 units/s per session, and the errors change sign:

```
N=8    measured  84.5   line  65.0   +30.0%
N=12   measured 122.4   line  97.5   +25.6%
N=16   measured 145.8   line 130.0   +12.2%
N=20   measured 176.8   line 162.4    +8.9%
N=24   measured 191.6   line 194.9    -1.7%
N=28   measured 194.7   line 227.4   -14.4%
```

A straight line through the origin cannot pass above the first four points and below the last two. **The script refused to quote a knee** — the check added an hour before this run, whose threshold is 5% and which saw 30%.

## Where the loss begins is the finding

The two-line model assumes sessions below saturation cost each other nothing. Background took 5.3 of sixteen cores, leaving about 10.7, and **twenty-eight sessions at duty 0.27 demand 7.6** — under three quarters of what is free, with per-session throughput already down a third.

At eight sessions the demand is 2.2 cores against 10.7 free, a fifth of the supply, and the fall has already started: twelve sessions are 3.4% worse per session than eight.

**So there is no regime where the sessions are free of each other**, and `total = N·d/w` describes none of this curve. What the machine has is a continuous decline, not a rise into a corner.

## What that costs and what it buys

**It costs the solo-free redline.** `redline = 2 × knee` was derived from the two-line model, and without a knee there is nothing to double. The [record that derived it](2026-08-02-204124-a-redline-without-a-solo-rung.md) stands as algebra and its measurement path is closed on this workload.

**It buys the shape a governor actually needs.** [M3 admits sessions against a measured ceiling](../../ROADMAP.md#m3--resource-governor), and a ceiling implies a place where the cost of one more session changes. There is no such place here: the marginal return declines from the first session onward. Admission cannot be *count against a threshold*; it has to be *what the next session takes from the ones already running*, which this curve gives directly — at twenty-four sessions, four more buy 3.1 units/s and cost the incumbents 13% of their rate each.

## What this run cannot say

- **One duty, one footprint, one machine.** 0.27 and 20 MiB. Whether the decline is this steep at other duties, or for a session holding gigabytes, is unmeasured.
- **The tail is drifting.** The last two references came back at 255.0 and 258.2 against 265.8–269.1 for the first five, a 5.34% spread the script reports as the floor. The 34% fall is six times that, and the first three points were taken while the references agreed to 0.94% — but the twenty-four and twenty-eight point figures carry the drift.
- **The absolute rate is not comparable to earlier runs.** The reference plateau is 264 where the same configuration gave 904 at noon; the machine had just returned from battery and the background was 33%. The curve is a within-run ratio and survives that, [as the same cancellation predicts](2026-08-02-121359-eta-follows-the-awake-count.md).
- **Nothing here measures `η`.** That was the run's purpose, and the model it depended on is what failed.

## 2026-08-02, later: this was recorded on 2026-07-30

*Sessions cost each other from the very first ones* is in the title of this
record and it is not new. [The duty relation's own
derivation](2026-07-30-154348-duty-is-derivable.md) says it three days earlier,
about ten sessions:

> Both got every core they asked for. Both ran slower anyway. **With six spare
> cores there is no scheduling contention to blame**, so the loss is what ten
> sessions do to each other through the memory system.

Reading the repository's reference list first is this project's own first rule,
and it would have said the two-line model was already contradicted before the
derivation that assumed it was written, let alone before a forty-minute sweep
went looking.

**What the sweep adds is the size and the shape across a range**: 34% per
session from eight to twenty-eight, a marginal return falling from 37.9 to 3.1,
and residuals whose sign flips — which is what turns *there is a loss below
saturation* into *admission is a price rather than a ceiling*. The 07-30 record
had one point and named the mechanism; this has six and prices it.

That is worth the run. It is not worth having gone looking for a knee that
the repository had already ruled out.
