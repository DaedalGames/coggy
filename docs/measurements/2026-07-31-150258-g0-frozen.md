# G0: the as-is redline, frozen · 2026-07-31 15:02:58

[G0](../../ROADMAP.md#current-priority-m0--attribution) asks for an as-is redline with its limiting cause named, for every reachable target, each reproducible from its hardware and each rigorous in the way its own limiting condition allows. This freezes it. Nothing here is remeasured once M1 begins; if the hardware changes, every target is retaken together.

## The headline

**A real generation session on this machine reaches nine, and memory is what stops it.**

| | |
|---|---|
| **Redline** | **9 sessions / RSS** |
| Range | 8.8 – 9.7 |
| Machine | Intel Core Ultra 7 356H · 16 logical (three tiers) · 31 GiB · Windows 11 (26200) |

**A session is one process COGGY spawns and everything it spawns in turn**, which for generation means an agent CLI and the engine it runs. That is not a modelling choice: [job object membership is inherited downward](2026-07-30-101141-conhost-and-defender.md), so the daemon that launches the agent owns the engine too, and the instrument measures the pair because the kernel groups them. Read the two as separate sessions instead and this ceiling is 11.7 rather than 9.

Both halves are therefore on one budget:

| | Per session | Rigour |
|---|---|---|
| Unreal 5.8 cooking | 1.87 GiB ± 6.4% | [five readings](2026-07-31-045604-an-error-bar-for-the-engine.md), drift control +0.8% |
| Agent CLI, resident | 0.52 GiB | [sawtooth 480–586 MiB](2026-07-31-054657-the-driven-duty.md) across a compaction |
| **Together** | **2.39 GiB** | `21.97 ÷ 2.39` |

**There is no slope to fit here and none is missing.** Total memory is the per-session figure times the count by construction, so repeats and a drift control are the whole of an RSS redline's rigour — and both are in hand, without the 22 GiB a ramp to nine would have needed.

## Cores do not bind, and the margin is smaller than it looks

| `d` | Ceiling | |
|---|---|---|
| 0.112 | 223 | an idle session waiting on a human |
| **0.27** | **93** | [measured two ways agreeing to 2.6%](2026-07-31-054657-the-driven-duty.md) |

93 against 9 is not a close call, so **the limiting cause is named with confidence even though the core figure is soft**. Two things keep it soft, and both are recorded rather than resolved: the relation has [never been exercised below duty 0.75](2026-07-30-154348-duty-is-derivable.md), and `C` counts [three tiers spanning 2.1× as one number](2026-07-31-145412-the-cores-are-not-interchangeable.md). Neither could move 93 to below 9.

Those three carry a fitted crossing through six saturated rungs and a drift check, on a workload holding 80 MiB — memory-bound, which is the shape a real session has.

**The pseudoconsole row was retaken after this freeze and now meets the standard** — 14 sessions, fitted at 14.1 through five saturated rungs, drift +0.5%, with two processes and one conhost per session on every rung. **It still does not compare to the pipes redline of 27**, because a single session ran at half the rate nine hours later and ten sessions received seven cores where they had received ten: [the machine changed between the two ramps](2026-07-31-151821-the-pseudoconsole-row.md), and nothing in the instrument checks for that.

The comparison does not block the freeze because **the decision it would have informed was settled by arithmetic first**. [Decision 1](../PLAN.md#four-core-decisions) claimed dropping conhost was worth half the project; a conhost is 8.7 MiB against a 2.39 GiB session, which is 0.35%. [The attribution rule fired and was honoured](../../ROADMAP.md#current-priority-m0--attribution) on that, and the decision now stands on process count. A redline for the pseudoconsole transport would refine a number nothing depends on.

## What the freeze binds M1 to

- **Nine sessions is the target to beat**, and it is a memory target. An M1 daemon that improves scheduling improves nothing here.
- **The agent CLI is the floor.** 0.52 GiB is held for a session's whole life against the engine's 1.87 GiB paid only while it cooks, so the first sessions cost the most and admission is about residency rather than activity.
- **Admission has a form**: `N ≤ 2ηC/d` for cores, `N ≤ budget / bytes` for memory, and on this machine the second is what fires.

## What a reader must not take from this

- **It is a laptop.** An Intel Core Ultra 7 356H on a vendor power plan, with three core tiers. Ceilings here are ceilings for that, and the relation's `C` is the term that does not travel.
- **The engine figure is one project.** `TP_BlankBP` cooked for Windows, where [the editor rather than the content dominates](2026-07-31-043951-the-editor-is-the-cost.md). Where that stops being true is the largest open assumption behind the nine.
- **The agent figure is one CLI and one session**, 26 hours old, driving a Rust repository rather than an engine.
- **Ten concurrent cooks remain unmeasured**, [blocked on 23.9 GiB against the 10.3 available](2026-07-31-042802-the-lock-reaches-cooking-too.md), and the shared shader cache is why they might differ from four.
